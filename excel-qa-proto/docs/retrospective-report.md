# 数净 DataClean QA 原型 · 回顾分析报告

日期：2026-08-19 · 对象：`excel-qa-proto/index.html`（单文件，1361 行，JS 1044 行，11 个模块）
方法：对照任务初期要求逐条核验 + 代码事实核查（非凭记忆，已实际运行验证）

---

## 一、系统现状总览

**架构**：`MockData / ExcelIO / Validator / Mart / QueryEngine / NLU / LLMClient / Chat / EvalRunner / UI / Store` 十一模块，数据流为：
上传 Excel → 表头门禁 → 原始表标注预览 →（手动）校验修复 → 清洗表 + Mart 预计算 → 双通道抽参 → 消毒 → 仲裁 → 本地查询 → LLM 组织回答 →（可选）文本校验。

**设计**：单文件 vanilla 栈，深青商务风；上排「数据管线 + 表单」、下排「全宽对话」；表格支持排序/门店品类筛选。

**性能**（234 行模拟数据实测）：
- 校验修复、Mart 构建、查询执行均为毫秒级纯本地计算；
- LLM 调用为唯一延迟源：单问 2 次串行调用（抽参 ~1200 token prompt + 组织 ~400 token），15s 熔断；开启二次校验后 3 次；
- 成本控制：全量数据不出本地（只发 schema+枚举+结果摘要）、max_tokens 硬限、记忆 12 条截断、JSON mode 一次重试封顶。

## 三、实际实现 vs 宣称完成（诚实清单）

**宣称且实际完成**：表头校验、标注预览、Mart（含环比/同比/排行/季度桶）、双通道仲裁、spec 消毒器、ratio/range/quarter/year 四扩展、评测 harness（22/22）、表头排序筛选、标题切换。

**宣称了但实际未完成或打折**：
1. **LLM 通道评测缺席** — 设计文档承诺"LLM 通道勾选后跑"，实际 `EvalRunner` 只有规则通道（代码核查 `hasEvalLLM: false`）；
2. **规则通道无多轮记忆** — `lastUserQ` 只传给 LLM（`ruleUsesLastQ: false`），降级到规则引擎后"那 8 月呢"类追问能力依赖巧合（恰好含月份词），非真正的上下文合并；
3. **groupBy year 未暴露** — Mart 预计算了年度桶，但 spec 白名单不含 `year` 分组，"各年销售额对比"会落到规则兜底的 store 默认分组，答非所问；
4. **真实 LLM 端到端未验证** — JSON mode、仲裁分支、verify 校验员均只经过 node 端模拟，未跑过真实 API。

## 四、偏差分析：正面 vs 负面优化

**正面优化（超出初期要求且方向正确）**：
- 表头门禁 + 同义别名纠错建议——把"传错文件"从静默错误变成明确反馈；
- 原始表双色标注预览——让"校验规则做了什么"对用户可见，建立信任；
- Mart 预计算层——环比/同比/排行 O(1) 命中，同时支撑了 spec 扩展；
- 双通道仲裁——把校验从文本层前移到结构层，且不打扰用户（符合"保流畅度"决策）；
- 评测集 22/22——准确度从"体感"变成"可回归"，首跑即揪出 2 个真实 bug（阈值语序、指标抢词）；
- year/quarter/ratio/range 扩展——全部由评测/真实问法驱动，非预设过度设计。

**负面优化（偏离初衷或有代价）**：
1. **prompt 膨胀 vs 降本初衷** — few-shot 从 0 涨到 9 条，抽参 prompt ≈1200 token，是初期的 3~4 倍。准确度收益真实，但与"尽可能降低资金成本"存在张力，应关注精简或示例外置；
2. **仲裁计数可能虚高** — `JSON.stringify` 字面比对，语义相同但字段表述不同（如 month vs year 等价表达）会误判"不一致"，仲裁统计偏乐观地反映分歧率；
3. **降级体验断裂** — 双通道仲裁让 LLM 在场时很稳，但一旦无 Key，规则引擎既无记忆又无歧义处理，体验落差大（这是"永不无响应"的代价：有响应≠答得准）；
4. **单文件规模逼近可维护性边界** — 1361 行单文件，11 个 IIFE 模块挤在一个 script 标签里，继续加功能应先考虑拆分；
5. **表格筛选与问数不联动** — 用户在表格里筛选"华东旗舰店"后问"销售额多少"，问数查的仍是全量。未要求实现，但交互上易误解。

## 五、结论与建议

**结论**：原型完整覆盖初期全部硬性要求，核心链路（校验修复 + 结构化问数）真实可用；四项"较大问题"中的三个（可度量、第一公里校验、表达力）已闭环，剩下"歧义无澄清"是按用户决策有意放弃。

**建议优先级**（如需继续迭代）：
1. 补 LLM 通道评测开关（兑现设计承诺，30 行内）；
2. 规则通道补上下文合并（lastUserQ 时间/维度条件继承，消除降级断裂）；
3. 开放 groupBy year（Mart 已有，一行白名单）；
4. 真实 API Key 端到端实测一轮（重点验证 JSON mode 与仲裁分支）；
5. 评估单文件拆分时机（>1500 行前）。
