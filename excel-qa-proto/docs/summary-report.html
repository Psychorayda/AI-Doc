1. 项目概述与核心指标

本项目是一个纯前端功能原型：用户上传 Excel 销售流水数据，系统按预设规则完成校验修复并剔除异常数据，随后将清洗结果预计算为标准化结构（Mart），对外提供自然语言问数能力——用户用中文提问，系统通过「大模型抽参 + 本地规则引擎」双通道将问题编译为结构化查询，在本地数据上执行并生成带数字依据的回答，支持多轮追问记忆。

2. 系统上下文图

系统边界极简：单页应用运行在浏览器内，唯一外部依赖是 SheetJS（CDN，Excel 解析）与用户自备的 OpenAI 兼容大模型 API。

3. 分层架构与模块依赖图

系统采用四层单向分层：上层可依赖下层，下层对上层无感知。全部 17 个模块、26 条 import 边经审计无循环依赖；唯一高扇入节点是 core/store（全局状态）与 qa/nlu（意图解析），二者均为地基型模块，符合稳定依赖原则（被依赖者最稳定）。

图 3-1 分层架构图：UI → QA → Data → Core 四层单向依赖（Brooks Audit 全部节点判定 clean）

依赖规则

  • ui/：唯一感知 DOM 的层；main.js 是装配根（Composition Root），所有跨层组装只发生在这里。
  • qa/：问数引擎，零 DOM 依赖，chat 通过构造函数注入 {store, llm, view} —— 这是关键的可测性接缝（Seam），Node 环境可注入 stub 做 headless 仲裁测试。
  • data/：纯逻辑无内部依赖；excel.js 仅在函数内引用全局 XLSX，CDN 失败不拖垮模块图。
  • core/：零内部依赖；store.js 是被 8 个模块依赖的高扇入地基，接口仅 17 行，变更成本极低。

6. 问数引擎：双通道仲裁机制

准确度的核心设计：同一个问题由规则通道（本地零成本）与 LLM 通道（语义理解强）各自独立产出结构化查询 spec，经消毒、月份消歧后进入仲裁器。仲裁对用户完全透明，不打扰对话。

为什么这样设计：LLM 单独抽参存在幻觉风险（编造枚举值、漏掉年份），规则单独解析覆盖面有限（问法千变万化）。双通道并行后，一致时高置信直接执行；不一致时按「有数据优先」择优——宁可采纳 LLM 的语义理解，也要在 0 命中时回退规则的保守解析，二者缺陷互补。

符号错误２５．５（全角）、¥32.5、1,280修正全角转半角 → 剥离货币/千分位/空白符号

10. 架构审计结论（Brooks Audit）

依据 Brooks-Lint 架构审计框架（六大衰变风险 + 可测性接缝 + 康威定律）逐项扫描，结论如下：

审计项结论依据
循环依赖通过26 条 import 边全部沿 ui→qa→data→core 方向，无任何回边
依赖方向通过无下层依赖上层的「向上箭头」；Store/config 两个高扇入模块均为最稳定地基
领域模型通过模块名即业务词汇（validator/mart/nlu/query），无万能 services 层、无跨边界逻辑渗漏
知识重复通过同一概念单点实现：聚合只在 query.js、月份消歧只在 nlu.js、圆整只在 mart/query 各一处语义明确
偶然复杂度通过每个模块职责可用一句话陈述；无空转层；Store 有意保持 17 行极简
变更传播（爆炸半径）通过最大爆炸半径为 Store 字段变更（影响 8 个模块），但字段语义稳定；规则/解析器扩展均为开闭式插入
可测性接缝通过chat（注入 store/llm/view）、llm（注入 fetchImpl）、config（环境自适应）三处工厂注入接缝，单测零 DOM 零网络
康威定律N/A单人项目，无跨团队协调面；分层即未来拆团队的天然边界
综合评级：健康。重构达到了预期目标——对照存档的 legacy-single-file.html，同一系统从「单文件、不可测、改一处动全身」演进为「四层单向依赖、三层可 headless 测试、模块独立可复用」的结构，且重构全程由单测守护无回归。

12. 设计决策与经验总结

关键决策回顾

  1. 「大模型只做翻译，不做计算」——数值计算全部本地化，LLM 只负责语义↔结构的双向转换。这同时解决了三件事：成本（prompt 不含数据）、准确度（数字不会 hallucinate）、响应（查询毫秒级）。
  2. 预计算 Mart 作为问数与数据之间的防腐层——修复后的明细数据被立即编译为标准化聚合结构，问数引擎面向 Mart 而非裸数据工作，环比/同比/排行类问题从 O(n) 计算变为 O(1) 查表。
  3. 双通道仲裁而非单通道信任——用规则的确定性约束 LLM 的创造性，仲裁策略「有数据优先」在不打扰用户的前提下消解分歧，且全程留痕（arbCount）。
  4. 两段式装载（预检不转正）——同一 Validator 结果先用于原始表标注、用户确认后转正，既实现「所见即所得」的修复预览，又避免重复计算，还把「修复」显式建模为用户决策而非系统黑箱。
  5. 降级链而非异常链——每一层外部依赖（CDN、LLM、JSON 解析、二次校验）都有明确的下一棒，最终兜底是纯本地模板回答。「永不无响应」是被设计出来的，不是测出来的。
  6. 模块化重构以接缝先行——先确立依赖注入边界（chat/llm/config 三处工厂），再按层拆文件，使重构本身可被单测验证，最终交付的不仅是文件拆分而是可独立复用的模块。

已知边界与后续方向

  • 问法覆盖以中文经营分析场景为主，极口语化或多跳推理问题（如"先算 A 再和 B 比"）超出单 spec 表达能力，可演进为多步查询计划。
  • 数据规模为演示级（数百行），全部计算在内存中同步完成；十万行以上需引入 Web Worker 或分片预计算。
  • 校验规则目前硬编码于 validator，若面向多业务场景可外置为规则配置 + 规则库版本管理。
  • LLM 通道评测消耗真实 token，黄金集建议保留为上线前门禁而非日常回归。
项目结论：原型全部既定目标达成——Excel 接入与表头门禁、7 类规则校验修复、可视化标注与指标、预计算 Mart、自然语言问数（双通道仲裁 + 多轮记忆 + 二次校验）、黄金集评测体系、模块化四层架构。系统以 1843 行零依赖（仅 SheetJS CDN）的体量，验证了「本地结构化查询 + 大模型语义翻译」这一低成本高准确问数范式的可行性。
