# 问数准确度提升设计（A 评测驱动 + C 双通道仲裁 + D spec 扩展）

日期：2026-08-19 · 状态：已确认 · 目标文件：`/workspace/excel-qa-proto/index.html`（单文件原型）

## 背景与问题

当前链路（标准化存储 → LLM/规则抽参 → 消毒 → 本地查询 → 组织回答）存在四大缺陷：
1. 准确度无法度量，prompt/规则改动无回归保障；
2. 单趟抽参无澄清机制，歧义问题产出"自信的错误答案"（用户已决策：不做二次确认，保流畅度）；
3. 结果校验在文本层（最后一公里），无法发现 spec 理解错误（第一公里）；
4. spec 表达力不足：无占比/阈值/季度。

## 设计

### C · 双通道仲裁（不改交互）
`Chat.ask` 中规则引擎与 LLM 并行抽参，统一过 `sanitizeSpec` 后结构比对：
- 一致 → 执行，meta 标「双通道一致」；
- 不一致 → 自动仲裁：优先 LLM spec；若其结果 0 命中而规则 spec 有命中则改用规则结果；meta 标「双通道仲裁」，仲裁计数入左栏统计卡（第 5 卡）；
- 无 Key → 单通道规则（现状不变）。

### A · 评测 harness
新增 `EvalRunner` 模块 + 约 20 条黄金问数集（问题 → 期望 spec 关键字段 → 期望命中行为 >0/===0）。
左栏「运行问数评测」按钮（校验完成后可用），弹窗报告通过率与失败明细。规则通道离线零成本。

### D · spec 扩展（评测集驱动）
- `ratio`：子集/时间范围总体 → 百分比；
- `filters.range`：`{field:price|qty|amount, min, max}` 阈值过滤；
- `filters.quarter`：`YYYY-Qn` + `groupBy:'quarter'`，复用 Mart 季度桶；
- NLU prompt 与规则引擎同步支持；`Mart` 导出 `qOf`。

## 数据流

问数 → 双通道抽参 → 消毒 → 仲裁（结构比对/命中数优先）→ 查询（Mart 优先）→ 组织回答 →（可选）文本校验。沿用"永不无响应"兜底。

## 验收

- 黄金集规则通道通过率 ≥ 90%；
- 「2024年销售额」命中 0 如实回答；「占比/阈值/季度」类问题可答；
- 双通道仲裁计数可见；全部既有用例回归通过。
