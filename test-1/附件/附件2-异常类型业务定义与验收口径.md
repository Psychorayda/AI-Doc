# 附件 2：异常类型业务定义与验收口径

本附件只回答两件事：**业务上什么算异常**，以及**使用者会怎么复核**。

**怎么检测是你要解决的问题**——算法选择、基线口径、聚合方式、阈值默认值，
都由你自主设计，并在设计说明文档中论证。本附件不提供实现方法与参考代码。

---

## 1. 五类异常的业务定义

| 编号 | 名称 | 业务含义 | 为什么要管 |
|---|---|---|---|
| **A1** | 金额异常高 | 单笔销售金额显著高于同类交易的常规水平 | 可能是串码、大宗倒卖，或未备案的团购业务 |
| **A2** | 单价异常低 | 成交单价明显低于该品牌的标准零售指导价，即**价格倒挂** | 行业敏感事件，常见成因为串货、跨区低价倾销、临期清货 |
| **A3** | 单价异常高 | 成交单价明显高于标准零售指导价，即**价格虚高** | 多见于节前紧俏时段的加价销售，属价格违规 |
| **A4** | 日聚合暴涨 | 某品牌在某一天的销售额整体大幅放大 | 单看每一笔都可能不出格，但当日总量已明显异常，需核查是否集中调货 |
| **A5** | 销售中断 | 某零售户长时间没有任何销售记录 | 可能已停业、转让，或转向非正规渠道进货 |

**本题只考察以上 5 类**，不需要也不建议自行扩展类别——
多报的类别会计入告警总数，受自评表第 8 项「误报控制」约束。

### 三条业务口径说明

1. **A2 / A3 是对标"标准零售指导价"，不是对标销售金额的分布。**
   各品牌标准价见题面第二节，可直接写入代码。

2. **"显著"到什么程度算异常，由你定义。**
   但你选的口径必须写进设计说明，并在系统里以可配置参数的形式存在
   （自评表第 10 项）。

3. **每条告警都要能回答"偏离了多少"。**
   只说"这条异常"不够，必须给出：实际值、你判定所依据的基线或正常区间、
   两者之间的偏离程度（自评表第 7 项）。

## 2. 清洗与检测的边界

数据清洗的目标是**修正格式问题**（日期格式、金额单位、全角字符、缺失值推导等），
**不是剔除业务上不寻常的记录**。

请谨慎设计"剔除"规则：一条记录金额很大、单价偏离标准价，
不构成剔除它的理由——那恰恰是后续检测要找的东西。
清洗阶段只应剔除**无法参与计算**的行（如名称为空、数量 ≤ 0 且无法推导）。

> 自评表第 3 项会单独核查这一点。

---

## 3. 核验者复核口径（契约）

评分时，使用者会用**你系统的默认参数**跑一遍，并按下列口径复核。
请确保你的系统在默认参数下就能正常工作，不需要核验者手动调参才出结果。

| 项目 | 复核口径 |
|---|---|
| 参考默认值 | 若采用 IQR 类方法，默认系数取 **1.5**；单价偏离阈值 **15%**；销售中断阈值 **14 天**。你可以选择其他默认值，但需在设计说明中论证 |
| 检出核对 | 核验者持有一份内部核对清单（不提供给练习者），逐条核对你的检出情况 |
| 误报控制 | 统计你在默认参数下产出的**告警总数**，按自评表第 8 项计分 |
| 数值一致性 | 同一份数据连跑两次，`实际值 / 基线 / 偏离度` 三项必须完全一致 |
| 阈值可调 | 使用者会现场调整一次阈值，检查结果是否实时刷新 |

### 关于"数字必须由代码计算"

这是本题（以及另外两题）的共同硬性要求：

- **可以由大模型生成**：原因推测、处理建议——即预警报告里的
  `explanation` 与 `suggestion` 两个字段；
- **必须由代码计算**：其余所有数值字段。

复核方式很简单：**同一条异常重跑一次，数字必须一模一样。**
大模型生成的数字会漂移，一跑就露。
