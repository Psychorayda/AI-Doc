# 附件 3：预警报告输出规范

工具须能导出一份 JSON 格式的预警报告（文件名建议 `alerts.json`），供后续系统对接。
评分时按本规范逐字段核对。

> ⚠️ **本文中所有示例数据均为虚构**——零售户名称、日期、金额、基线值都是编造的，
> 与赛题数据没有任何对应关系，**不要拿去核对你的检出结果**。
> 示例只用于说明字段结构与类型。

---

## 1. 顶层结构

```json
{
  "meta": {
    "生成时间": "2026-07-29T14:30:00",
    "数据文件": "附件1-卷烟销售流水_原始.xlsx",
    "原始行数": 553,
    "清洗后行数": 0,
    "检测参数": { "方法": "你使用的方法名", "k": 1.5, "单价偏离阈值": 0.15, "中断天数阈值": 14 }
  },
  "summary": {
    "异常总数": 0,
    "按类型": { "A1": 0, "A2": 0, "A3": 0, "A4": 0, "A5": 0 },
    "按严重度": { "高": 0, "中": 0, "低": 0 },
    "涉及零售户数": 0,
    "涉及金额": 0.0
  },
  "alerts": [ ]
}
```

- `原始行数` 固定为 553（赛题数据行数）。
- `清洗后行数`、`summary` 各项由你的实现填写，**须与你的清洗日志和告警清单自洽**。
- `检测参数` 须如实反映本次运行实际使用的参数。

---

## 2. 单条预警（`alerts` 数组元素）

**以下为虚构示例：**

```json
{
  "alert_id": "AL-0001",
  "type": "A1",
  "type_name": "金额异常高",
  "level": "高",
  "scope": "record",
  "locator": {
    "原始行号": 999,
    "销售日期": "2025-01-01",
    "零售户名称": "示例零售户",
    "许可证号": "wholesale3400000",
    "卷烟品牌": "示例品牌"
  },
  "metric": "销售金额(元)",
  "actual": 88888.0,
  "baseline": {
    "方法": "你的基线方法说明",
    "样本数": 100,
    "正常区间": [0.0, 10000.0]
  },
  "deviation": { "值": 78888.0, "倍数": 8.89, "描述": "为正常上界的 8.89 倍" },
  "explanation": "（由大模型生成的原因推测）",
  "suggestion": "（由大模型生成的处理建议）"
}
```

### 字段要求

| 字段 | 必填 | 说明 |
|---|:--:|---|
| `alert_id` | ✓ | 报告内唯一 |
| `type` | ✓ | `A1`–`A5`，见附件 2 第 1 节 |
| `type_name` | ✓ | 类型中文名 |
| `level` | ✓ | `高` / `中` / `低`，分级口径由你定义并写入设计说明 |
| `scope` | ✓ | `record`（行级）/ `daily`（日聚合）/ `retailer`（零售户级） |
| `locator` | ✓ | 定位信息；聚合级告警可省略 `原始行号` |
| `metric` | ✓ | 被检测的指标名 |
| `actual` | ✓ | 实际值（数值型，不带单位与千分位） |
| `baseline` | ✓ | 基线信息，**必须包含判定所用的正常区间或基准值**；具体子字段随你的方法而定 |
| `deviation` | ✓ | 偏离程度，须同时给出数值与可读描述 |
| `explanation` | ✓ | 原因推测（可由大模型生成） |
| `suggestion` | ✓ | 处理建议（可由大模型生成） |

---

## 3. 聚合级告警的结构差异

聚合级告警（`scope` 不是 `record`）的 `locator` 与 `metric` 与行级不同，
且建议增加一个 `detail` 字段，说明这条告警由哪些明细构成。

**以下两段均为虚构示例：**

### `scope: "daily"`

```json
{
  "alert_id": "AL-0002",
  "type": "A4",
  "type_name": "日聚合暴涨",
  "level": "中",
  "scope": "daily",
  "locator": { "销售日期": "2025-01-01", "卷烟品牌": "示例品牌" },
  "metric": "当日销售额合计(元)",
  "actual": 66666.0,
  "baseline": { "方法": "你的基线方法说明", "基准值": 10000.0 },
  "deviation": { "值": 56666.0, "倍数": 6.67, "描述": "为基准值的 6.67 倍" },
  "detail": { "涉及笔数": 0, "涉及零售户": ["示例零售户A", "示例零售户B"] },
  "explanation": "……",
  "suggestion": "……"
}
```

### `scope: "retailer"`

```json
{
  "alert_id": "AL-0003",
  "type": "A5",
  "type_name": "销售中断",
  "level": "中",
  "scope": "retailer",
  "locator": { "零售户名称": "示例零售户", "许可证号": "wholesale3400000" },
  "metric": "连续无销售天数",
  "actual": 30,
  "baseline": { "方法": "你的基线方法说明", "阈值天数": 14 },
  "deviation": { "值": 16, "倍数": 2.14, "描述": "超出中断阈值 16 天" },
  "detail": { "中断起": "2025-01-01", "中断止": "2025-01-31" },
  "explanation": "……",
  "suggestion": "……"
}
```

---

## 4. 硬性约束

1. **所有数值字段必须是数值类型**，不得是 `"￥1,234.00"` 这样的字符串——
   这是清洗是否到位的直接体现。
2. **`actual`、`baseline`、`deviation` 三者必须来自代码计算**。
   大模型只允许生成 `explanation` 和 `suggestion` 两个字段。
   这两个字段中**可以复述**上述三项已算好的数字，但**不得出现任何新数字**。
   评分时会抽查：把同一条告警重新跑一遍，三个数值字段必须完全一致
   （大模型生成的会漂移）。
3. `alerts` 数组需按 `level`（高→低）、再按 `deviation.倍数`（大→小）排序。
4. JSON 文件须为 UTF-8 编码，可被 `json.load()` 直接读取。
5. 没有检出任何异常时，`alerts` 为空数组，`meta` 与 `summary` 仍须完整输出。
